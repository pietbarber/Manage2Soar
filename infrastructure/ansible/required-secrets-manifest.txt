# This file is TRACKED in git and contains ONLY file paths (relative to the
# project root) -- it contains NO secret values. That makes it safe to commit
# and durable across machines.

# It lists every gitignored file that MUST be present in order to:
#   1. keep the Django site running (.env, service-account key), and
#   2. run the full set of Ansible playbooks (inventories, group_vars, DKIM).
#
# Every line below MUST satisfy all three of these (enforced by
# infrastructure/scripts/audit-ansible-secrets.sh):
#   - exists on disk
#   - is listed in .gitignore  (git check-ignore passes)
#   - is NOT tracked by git    (git ls-files does not match it)
#
# HOW TO KEEP THIS UP TO DATE:
#   ./infrastructure/scripts/audit-ansible-secrets.sh audit     # verify + detect missing
#   ./infrastructure/scripts/audit-ansible-secrets.sh list      # print the list
#   ./infrastructure/scripts/audit-ansible-secrets.sh tarball   # build the backup tarball
#   ./infrastructure/scripts/audit-ansible-secrets.sh sync      # refresh ~/bin list
#
# A pre-commit hook runs the METADATA-ONLY `check` mode (not `audit`) on every
# commit, so a clean clone / CI checkout is never blocked by missing local
# secrets. It enforces only: every entry is gitignored AND no entry is tracked.
# Run the FULL `audit` (adds "exists on disk") manually on provisioned boxes.
#
# NOTE: The Vault password is a FILE in this repo (convention: ~/.ansible_vault_pass,
# or the path named by ANSIBLE_VAULT_PASSWORD_FILE). Because it lives in the
# operator's home directory, not the repository, it is not a repo-relative path and
# is NOT listed here -- but it MUST be part of disaster-recovery/backup planning
# (see docs/runbooks/ansible-secrets-backup.md).
